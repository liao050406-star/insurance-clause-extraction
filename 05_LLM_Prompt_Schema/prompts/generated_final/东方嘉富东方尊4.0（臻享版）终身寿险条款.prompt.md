# 增额终身寿险条款字段抽取提示词 V2（最终版）

你是保险条款信息抽取助手。请仅根据当前条款正文，按照给定字段定义提取结构化信息。

## 任务

严格按照“字段定义”和“输出样例”的 JSON 形状提取当前产品，最终只输出一个合法 JSON 对象。

## 硬性约束

1. 只能依据“当前条款正文”，不得依据行业惯例、产品名称暗示、其他产品或输出样例补全当前产品。
2. 条款未载明或字段不适用时输出 `null`，不得猜测；数值 `0` 仅表示条款明确允许立即行使或明确为零。
3. 产品信息必须保留全部 13 个字段；保险责任每条必须保留全部 12 个字段；责任免除必须保留全部 5 个字段。
4. 不得增加字段、删除字段、输出 Markdown 代码围栏或解释文字。
5. 责任名称必须逐字采用条款名称；责任免除“原文”必须逐字摘录完整段落，包括引导语、各免责项目、段尾处理约定、脚注号和释义标记。
6. 同一保险责任因年龄、交费阶段不同而采用不同算法时，仍保留为一条责任，并在“赔付说明”中完整写明分段条件和算法。
7. 条款将身故与全残合并为同一责任时不得擅自拆分；条款分别列名时分别记录。
8. 赔付公式涉及“先取较大者再相加”时，必须在“赔付说明”中保留计算层次，不得简化为一次取大。
9. 比例使用不带百分号的小数：1.75% 写为 `0.0175`，160% 写为 `1.6`；金额使用元，天数使用天，年龄使用周岁整数。
10. “保额递增比例”表示条款明确规定的保险金额增长规则，不得表述为收益率、预定利率或红利水平。
11. 必须区分固定比例递增与红利保险金额累加。红利不保证、某些年度可能为零时，不得将身故给付公式中的系数误认为固定保险金额增长率。
12. 投保年龄只有在条款给出具体上下限时才填写。若条款仅写“符合我们的要求”等非具体表述，填写 `null`。
13. 保险期间应摘录条款原文；“至被保险人身故时终止”表示终身，但不得改写原文字段值。
14. “6个月”和“180日”保持各自条款口径，不得相互换算。
15. 等待期未载明或不适用时填 `null`；仅当条款明确写明等待期为零或无等待期时才填 `0`。
16. 减保规则必须辨认起始时间和比例计算基数；没有等待年限且合同有效期内即可申请时，“减保起始保单年度”填 `0`。
17. 阅读指引、目录、示例和案例中的投保金额或赔付金额不得作为产品固定字段值。
18. “出处”只填写直接支持该责任的条款编号，不得填写推测条号。
19. 若存在集中列示的其他责任免除提示，将其条款编号和范围写入“其他免责提示”；没有集中提示时填 `null`。
20. 输出前静默检查：字段是否齐全、枚举是否合法、比例和单位是否正确、`null` 与 `0` 是否混淆、责任名称与免责原文是否忠实。不要输出检查过程。

配套样例：`样例_中英鑫悦未来5号至臻版.json`（中英人寿，2025 版，分红型）

## 一、整体形状

| 表 | 记录数 | 字段数 |
|---|---|---|
| 产品信息 | 一份条款一条 | 13 |
| 保险责任 | 一条责任一条 | 12 |
| 责任免除 | 一组一条 | 5 |

合计 30 个字段，是规范允许的上限。增额终身寿的字段压力主要来自递增机制——比例、起算年度、复利还是单利，三件事缺一不可比。

**保险责任为什么有五条**：条款第 2.1 条只写了三条给付责任，但第 3.2 条红利章里还藏着一条「交清增额保险对应的身故保险金」，第 11 章还有「转换年金权益」。只抽 2.1 章的人会漏掉后两条，而这两条恰恰是增额寿产品之间差距最大的地方。

**转换年金权益为什么进责任表**：它是条款写明、各家有无不一、且直接影响养老场景可用性的权益，业务系统也把它作为一条 duty 记录。放进责任表，「哪款能转年金」一句话能查；单独设字段则要在产品信息表里加两个字段（有无、条件），更贵。

**减额交清（第 12 章）为什么不进表**：它改变的是后续保费与保额的计算基准，属于保全操作而非给付责任，抽进来会让「责任类型」这个枚举失去意义。写在坑那一节提醒即可。

> 注：年金险版设了「是否分红」字段。两版若要并表，建议统一取消该字段，改用「红利领取方式」判断。

### 递增机制怎么抽

条款 1.6 的原文是：当年度保险金额 = 上一个保单年度末的保险金额 ×（1+1.75%），首个保单年度等于基本保险金额。

拆成两个字段：`保额递增比例` = 0.0175，`递增起始保单年度` = 2。完整表述（复利、以上年度末为基数、首年不递增）写进保险责任表的赔付说明。

**这里的 1.75% 是条款正文写明的**，和产品备案里的预定利率不是一回事，也不要因为数值相同就混为一谈。同期的年金产品条款里往往找不到任何利率数字，抽取时必须区分「条款有」和「条款没有但业务系统有」。

| 必选或可选 | 枚举 | 必选 / 可选 |

| 已交保费给付比例上限 | 小数 | 年龄系数表的最高档；不涉及已交保费的责任填 `null` |
| 单次给付限额 | 数值（元） | 条款写明的累计给付上限；无上限填 `null` |

| 是否受责任免除约束 | 枚举 | 是 / 否；条款未明确的填 `null` |
| 赔付说明 | 文本 | 数值字段装不下的全部信息 |
| 出处 | 文本 | 条款第几条 |

### 填写要点

**一、身故保险金分三段，不要拆成三条记录。** 18 周岁前、18 周岁后且交费期满首个保单周年日前、之后——这是同一条责任的三种情形，不是三条责任。拆开的话「已交保费给付比例上限」这个字段在三条上完全一样，对比表里就成了三行重复。三段的差别写进赔付说明。

这和重疾险把 100%/130%/150% 拆成三条不同：重疾那是三次独立的给付，这里是同一次给付的三种算法。**判断标准是能不能同时发生，不是条款分了几段。**

**二、年龄系数表装不进数值字段。** 160%/140%/120% 三档只能在 `已交保费给付比例上限` 里放最高档 1.6 用于排序，完整的三档表写进赔付说明。这是规范里「数值字段装不下就用赔付说明兜底」的标准场景。

**三、「基本保险金额」被条款重新限定过。** 2.1 末句写明：三项身故保险金中所称的基本保险金额**不包括因红利分配产生的相关利益**。3.2 末段又写明：1.6 条约定的基本保险金额**不包括累积交清增额基本保险金额**。这两句是最容易漏抽的内容，漏了就会把红利买来的保额算进主险给付里。必须写进赔付说明。

**四、交清增额的身故责任填「可选」。** 它只在红利领取方式选了交清增额时才存在，`行使条件` 填明这一点。

**五、`是否受责任免除约束` 遇到条款没点名的，填 `null`。** 2.2 逐项列举了它管的三种保险金，没有提到交清增额身故金。这是条款本身的模糊，不是抽取者该替它补的。

## 四、责任免除

### 字段表

| 字段名 | 说明 |
|---|---|
| 适用范围 | 这一组免责管哪些保险金，**照抄条款列举的名称** |
| 免责条数 | 数值 |
| 原文 | 整段逐字抄，含引导语和段尾的处理约定 |
| 出处 | 条款第几条 |
| 值得关注的条目 | 一句话点出差异最大或最容易漏的部分 |

另附「其他免责提示」一条。**本产品条款没有这一节**，填 `null` 并注明，不要因为别家有就替它编一个。

### 为什么整段抄

引导语「因下列情形之一导致被保险人身故的，我们不承担给付身故保险金、重大自然灾害意外身故保险金、航空公共交通工具意外身故保险金的责任」——这一句同时确定了两件事：免责只管身故类给付，以及它一次管三条责任。拆成五条独立记录，这句就丢了。

段尾同样要抄。投保人故意杀害被保险人的，现金价值退给**被保险人的继承人（除投保人本人外）**，这是防止犯罪获利的设计。

原文里的「（见 15.10）」这类释义标注也要抄，删掉就不是逐字，也就没法拿输出和 PDF 做自动比对。业务系统的 `excltxt` 字段通常已经去掉了这些标注，这正是生产数据不能直接当答案的原因。

## 五、四条填写规则

**一、条款没写的填 `null`，不要猜。** 交费期间是最大的诱惑：条款 4.1 只说「由您与我们约定并在保险单上载明」，业务系统里有「1年 3年 4年 5年 6年 10年」，但那不是条款内容。

**二、`null` 和 `0` 要分清。** `null` = 条款没写或不适用，`0` = 条款写明是零。

本产品同时提供了两类的干净例子：

| 字段 | 值 | 为什么 |
|---|---|---|
| 等待期天数 | `null` | 增额寿不设等待期，是「不适用」 |
| 减保起始保单年度 | `0` | 条款 1.6 写明「在本合同有效期间内」即可申请，**是明确的零等待，不是没写** |
| 单次给付限额（身故保险金） | `null` | 条款未设上限 |
| 单次给付限额（重大自然灾害） | `6000000` | 条款写明 600 万元 |

减保这一条尤其值得对照：海港金彩颐年是「满 5 个保单年度后」，填 5；本产品是「有效期间内」，填 0。同为 20% 的年度上限，流动性完全不同，而这个差异只有靠 0 和 5 的区分才看得出来。填成 `null` 就丢了。

**三、单位与格式统一。** 比例用 0～1 小数（`0.0175` 不是 `1.75` 也不是 `"1.75%"`）；金额用元（`6000000` 不是 `600`）；天数用天；年龄用周岁整数。

注意 `已交保费给付比例上限` 是个例外——它是 1.6 而不是 0.6，因为给付比例本来就大于 1。规则是「小数不带百分号」，不是「必须小于 1」。

**四、`责任名称` 和免责 `原文` 逐字抄。**

## 七、增额终身寿特有的四个坑

**坑一：三个「保险金额」不是一回事。** 基本保险金额、当年度保险金额、累积交清增额基本保险金额，条款分别在 1.6、1.6、3.2 定义，且互相排除——1.6 的基本保险金额不含累积交清增额，2.1 的三项给付所称基本保险金额不含红利产生的利益。混用会把红利买的保额重复计入。

**坑二：递增的基数是上年度末，不是投保时。** 「当年度保险金额 = 上一个保单年度末的保险金额 ×（1+1.75%）」是复利。写成「基本保额 ×（1+1.75×年数）」是单利，长期差距很大。首个保单年度不递增，指数是 n−1 不是 n。

**坑三：减额交清会关掉分红。** 第 12 章末句写明「减额交清后，本合同将不再享有红利分配」。做长期利益演示时若假设中途减额交清，必须同时停掉红利，否则数字必错。这一条不在责任表里，只在条款正文，是最容易被结构化抽取整个跳过的内容。

**坑四：转换年金权益的结果不在本条款里。** 第 11 章只说可以把现金价值换成「我们当时提供的年金保险」，领取金额和方式以转换当时的产品为准。也就是说这项权益的具体价值在本条款中不可知。抽取时如实记录条件即可，不要替它假设一个年金水平。
