# 总验证报告（最终态）

> 本文件是方向一「条款提取与对比」的**最终态验证报告**，按课程要求的六项内容汇总，并作为 `09_validation_report/` 的索引，指路到各分报告。
>
> 最终态口径：增额终身寿险 · 五款产品 · 13 字段 · 65 行 Gold · 三模型（含两路独立盲测）· 12 条逐字金标。

---

## 1. 做了什么

建立了一条「PDF → 结构化字段 → 跨产品对比 → 验证」的可复现闭环：

1. **PDF 解析**：PyMuPDF/pdfplumber 提取文本层，产出 `raw` / `clean` / `canonical` 三种文本及页级质量报告。
2. **章节切分**：按条款编号切分正文，排除目录、页眉、复合页脚。
3. **Prompt 组装**：字段规范 + 输出样例 + 条款正文，组装成完整抽取提示词。
4. **LLM 抽取**：三模型对同一冻结 V3 输入独立输出结构化 JSON。
5. **代码校验**：结构校验（形状/字段/类型/枚举）+ Gold 对比 + 引用核验 + 逐字核对。
6. **对比与差异分析**：生成五款字段对比表，并由 LLM 依据已验证字段生成实质差异分析（逐条绑定条款号）。

验收范围：富泽泽瑞一生、恒安标准传世瑞盈 B 款、太保鑫相伴（2025）、新华 E 增福优享版、东方嘉富东方尊 4.0 五款终身寿险。

## 2. LLM 用在哪几步

| 步骤 | 是否 LLM | 说明 |
|---|---|---|
| PDF → 文本 | 否 | 代码确定性提取 |
| 章节切分 | 否 | 代码按条款结构切分 |
| 字段抽取 | **是** | 核心任务：依据条款正文 + 字段定义 + 样例输出结构化 JSON |
| 结构校验 / Gold 对比 | 否 | 代码校验，不做推测、不反填 |
| 差异分析文案 | **是** | 只消费已验证 13 字段，逐条绑定条款号，禁止优劣评价 |
| 三模型对比盲测 | **是** | claude_sonnet / claude_opus 用冻结 V3 输入独立运行 |

数字不经过 LLM：所有数值均来自条款原文，模型不得重算、推算、补全。

## 3. 提示词改了几版、关键改动

三个有效版本，保留在 `05_LLM_Prompt_Schema/prompts/`：

| 版本 | 文件 | 关键内容 |
|---|---|---|
| v1 初版 | `v1_initial.md` | 固定 JSON 形状、null/0 区分、比例单位、责任名称与免责原文逐字摘录 |
| v2 最终版 | `v2_final.md` | 补：投保年龄未载明必须 null、固定比例增长与红利保险金额累加分开、保险期间归一化、输出前静默自检 |
| v3 金标版 | `v3_gold_schema.md` | 从三段式 30 字段收敛为 **13 个可验证字段**；`guaranteed_growth_rate` 只记录进入保证给付公式的固定系数，不得表述为收益率/红利率 |

迭代记录与理由见 `DECISIONS.md`（D019、D035）。

## 4. 校验结果

### 4.1 结构校验

- 五款产品结构校验：**5 通过 / 0 拒绝**（`document_count=5`，`rejected_count=0`）。
- 逐字金标：**12/12 逐字一致、12/12 原文落位**（责任名称 7 条 + 免责原文 5 条）。

### 4.2 三模型盲测（13 字段 × 5 产品 = 65 项）

| 模型 | 身份 | 严格准确率 | 实质准确率（人工复核） |
|---|---:|---:|---:|
| codex_gpt5 | Gold 副本，**非盲测** | 100.00%（65/65） | 无泛化意义 |
| claude_sonnet | **独立盲测** | 52.31%（34/65） | 90.77%（59/65） |
| claude_opus | **独立盲测** | 58.46%（38/65） | 89.23%（58/65） |

- 严格口径把「语义等价但表述不同」一并判错，是**下界**；实质口径逐条人工复核，把 13 处真实分歧单列。
- 最弱字段（盲测）：`benefit_before_payment_end`、`benefit_after_payment_end`、`effective_sum_assured_definition`、`reduction_rule`、`policy_loan`（多为 0/5~1/5），归因详见四方对比报告。

### 4.3 关键口径说明

- 数值准确率与引用完整性分开统计。
- Gold 只读，SHA-256 运行前后一致：`e76ddd93c670b1581d686af81228273319b09b0a7a2f19ff1fa15cab38959942`。
- `codex_gpt5` 的 100% 仅证明结构与报告链路，**不代表泛化能力**；真实盲测水平以 claude_sonnet / claude_opus 为准。

## 5. 修了什么问题

- 恒安「符合我们的要求」时投保年龄被错误补全 → 改为 `null`（D013）。
- 「至被保险人身故时终止」未归一化为「终身」→ 评估口径归一化（D014）。
- 红利保险金额累加被误判为固定比例保额增长 → 分列机制（D012/D033）。
- 多栏目录被误识别为正文 → 太保正文从第 2 页开始（D024）。
- 复合页脚「个人保险基本条款第三版第 N 页」混入正文 → 页码元数据清理（D025）。
- 低文本密度误报扫描件 → 保留告警 + 人工判断，不自动 OCR（D026）。
- 太保产品错配（盛世鸿运 → 鑫相伴 2025）→ 替换 PDF 并重跑全流程（D030）。
- 空占位 Prompt 冒充迭代证据 → 删除并重排 v1/v2/v3（D019）。

## 6. 还有什么没解决

诚实列出，仍需后续处理：

1. **无未参与 Prompt 调优的独立盲测产品/测试集**：现有五款均参与过 Schema/Prompt 调优，B/C 盲测只能说明「换模型」的差异，不能完全代表「换产品」的泛化。
2. **赔付公式等长文本未逐字覆盖**：逐字金标仅覆盖责任名称 + 免责原文 12 条，`benefit_*`、`effective_sum_assured_definition` 等长文本仍以人工归纳口径，未逐字核对。
3. **扫描件 OCR 不支持**：只处理有可用文本层的 PDF，低文本密度仅告警。
4. **模型运行信息未完整记录**：模型名称、版本、temperature、运行环境未在产物中统一落档（D020）。
5. **数据来源与获取时点未标注**：合规清单要求此项，当前仅写「以 PRODUCT.md 为准」但 PRODUCT.md 未落地，待补。
